# 任务1 每周更新因子所需基础数据
目前我对财报的各项因子已基本满意，目前我的项目的存量数据仅截止到2026年7月，后续我要每周对项目数据进行动态更新，目前，必须每周动态更新的，是因子计算所需要的必要原始数据，帮我制定一个计划

1. 一键周更入口：在 src/data_fetch.py 新增一个每周更新编排函数，并在该文件的 if __name__ == "__main__" 中调用，运行后即完成全链路增量更新。
按依赖顺序增量更新必要原始数据：
- 交易日历 trade_cal（全量覆盖，作为最新交易日基准）；
- 股票清单 stock_list（捕捉新股上市/退市）；
- 每日指标 stock_daily_basic（改造为按各股已存最大交易日增量取数，是提速重点）；
- 周K行情 stock_weekly（沿用原生逐股增量）；
- 周K技术指标 stock_weekly_indicator（派生表，仅补缺失周）；
- 财报类（财务指标 stock_fina_indicator 及其占位字段回填、资产负债表、利润表、现金流量表）。

2. 注意事项：
- 有条件轮询财报：仅当处于财报披露高峰期（默认 4、8、10 月）时才轮询财报类数据，其余周跳过，显著省时；并提供参数强制包含或强制跳过。
- 数据新鲜度体检：更新结束后打印各表最新日期与最新交易日对比，一眼看出哪张表落后。
- 首轮自动回补：首次运行自动把 2026-07 至今约 2.5 个月的历史补齐，之后每周运行即为轻量增量。
边界与约束
- 只更新原始数据，不触发因子重算。
- 所有 upsert_* 幂等，函数可重复运行、可中断续跑。
- 不改动 main.py，不新建独立脚本，改动集中在 data_fetch.py 与 config.py。
- 因子截面日期由 trade_cal、stock_daily_basic、stock_weekly_indicator 三者交集决定，故这三张表必须每- 周更新，否则因子日期不会前进。

# 任务2 基于已经更新的基础数据，每周更新因子
因子是周频且每个截面独立计算（不依赖上一期因子），所以增量只需给一个 [start, end] 窗口，无需预热，且 upsert 幂等、可重复跑，但注意：例如波动因子等因子计算时，使用到了不止T日截面数据，还使用了T-N日的历史数据。所以增量更新时，要对部分因子的strat进行向前延展，并按start（即T日）作为最终输出的窗口起始，以保证因子增量更新的延续性。

1. 关键要点
- 窗口：start = stock_factor 现有 max(trade_date)（含边界，重算无害）；end = 今天。
- 需更新计算的因子：size / valuation / volatility / reverse / profit / growth / cash，签名统一为 (start_date, end_date)。
- 未实现，跳过的因子，supply / moat 。
- 事先要检查依赖是否已就绪：reverse 依赖 stock_weekly_indicator、其余依赖 daily_basic / 财报表，均已更新。
- 待更新的因子时序窗口为[start, end]，但部分因子由于计算依赖历史数据，需要向前延展，以保证因子增量更新的延续性。
耗时小：只跑新增的几周截面，分钟级。
