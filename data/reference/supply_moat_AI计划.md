# supply / moat 因子 · 基于 MD&A 文本的 AI 分析定向计划

> 2026-10-13 ｜ 针对「用年报/半年报 MD&A 大规模文本 AI 分析 → supply（行业供需景气度）+ moat（护城河）」这一目标
> 状态：计划（未执行）

---

## 0. 对前案的纠正

前一份方案把 supply/moat 设计成**结构化财务指标**（用 `stock_fina_indicator` 的 roic/grossprofit_margin 等）是**错误的**。本计划按真实目标重做：

- **supply** = 从年报/半年报 **MD&A（管理层讨论与分析）** 文本，提炼公司所处**行业的供需景气度**（行业维度属性，赋予个股）。
- **moat** = 从 MD&A 文本，提炼公司**护城河**（品牌 / 资格牌照 / 成本 / 渠道 / 技术专利 / 转换成本 等优势）。
- 产出落库到 `stock_factor.supply` / `stock_factor.moat`（int，[-100,100]，与现有 7 因子同尺度）。

> 实测前置现状：项目**无任何 MD&A 文本基础**——无文本表、无 PDF 解析库、无 LLM 依赖；`stock_factor` 已有 `industry` 字段可复用（避免让模型识别行业）。

---

## 1. 总体架构（数据流）

```
[MD&A 源]   cninfo 年报PDF / 文本版年报 / iFinD-Wind
    │  (抓取 + 版面解析抽取"管理层讨论与分析"章节)
    ▼
[stock_mda]  新建文本表: ts_code, end_date, ann_date, report_type,
    │         mda_text, char_len, source, parsed_at
    ▼
[AI 分析]   批量调用 LLM (长上下文 API) ── 结构化 JSON 输出
    │        ├─ supply: 行业供需格局 + 景气度趋势 + 产业链位置
    │        └─ moat:   六维护城河识别 + 强度 + 证据引用
    ▼
[评分映射]  定性档位 → 数值 → 标准化 (supply 行业中性 / moat 全市场)
    │        季频结果 → 前向填充到周频截面
    ▼
[stock_factor]  upsert supply / moat 列
    ▼
[验证]      analyze_factor_ic.py → 相关性矩阵(去冗余) + IC/IR + 人工抽检
    ▼
[自动化]    财报季(4/8/10月)增量: 抓新MD&A → 增量分析 → 填充更新
```

## 2. 阶段一 · 数据源与文本获取（最关键，前置依赖）

### 2.1 获取途径对比

| 途径 | 内容完整性 | 成本 | 工程难度 | 评价 |
|---|---|---|---|---|
| **cninfo 年报 PDF** | 最全（官方源） | 免费 | **高**（PDF 版面解析 + OCR，扫描件多） | 自主可控；用户已有 cninfo 爬取经验可复用 |
| 东方财富/新浪 文本版年报 | 较好（HTML 文本） | 免费 | 中 | **性价比最高**，优先验证是否可稳定拿到 MD&A 文本 |
| 同花顺 iFinD / 万得 Wind | 结构化 MD&A 文本 | 付费账号 | 低 | 若有账号，直接大幅降本，跳过解析 |
| Tushare / akshare | **无 MD&A 全文**（仅主营构成/审计意见） | 免费 | — | 不可用，排除 |

### 2.2 推荐路线
1. **首选**：东方财富/新浪文本版年报 → 正则抽取「管理层讨论与分析」章节（HTML 比 PDF 易解析，失败率低）。
2. **兜底**：cninfo PDF → `pdfplumber`/`pypdf` + 版面树定位章节 + 扫描件走 OCR（PaddleOCR）。
3. **若有 iFinD/Wind**：直接用其结构化 MD&A 字段，阶段一几乎归零。

### 2.3 入库表设计（新建）
```
stock_mda(
  ts_code      VARCHAR(20),
  end_date     VARCHAR(20),   -- 报告期 YYYYMMDD (0331/0630/0930/1231)
  ann_date     VARCHAR(20),
  report_type  VARCHAR(4),    -- '年报'/'半年报'
  mda_text     TEXT,
  char_len     INTEGER,
  source       VARCHAR(20),
  parsed_at    DATETIME,
  PRIMARY KEY (ts_code, end_date)
)
```
> 取数复用现有 `get_fina_indicator_by_ann_date` 的「ann_date 窗口 + 上市日过滤」逻辑，保持截面口径一致。

## 3. 阶段二 · 文本处理管线
- **章节定位**：年报结构固定，用标题树（「管理层讨论与分析」「经营情况讨论与分析」）正则定位起止，截取到「重要事项」之前。
- **清洗**：去页眉/页脚/页码、去表格噪声（MD&A 偶含小表格，优先保留叙述文本）、去页内冗余重复。
- **长文本分块**：单份 MD&A 常 1–3 万字，超多数模型窗口。
  - 方案：按自然段落切块（≤4k 字/块）→ 逐块摘要 → 合成行业/护城河维度摘要 → 再评分（**摘要链**，避免截断丢信息）。
  - 或直接用支持长上下文的模型（GLM-4-Long / DeepSeek 长窗 / Gemini 1.5）一次喂入。

---

## 4. 阶段三 · AI 分析（核心）

### 4.1 模型选型（批量 + 长上下文 + 低成本）
| 候选 | 长上下文 | 单价 | 适配度 |
|---|---|---|---|
| **DeepSeek-V3 / R1** | 64k–128k | 极低 | 主力推荐 |
| 智谱 **GLM-4-Long** | 128k–1M | 低 | 长文本首选 |
| 通义 **Qwen-Long** | 1M | 低 | 长文本备选 |
| OpenAI **GPT-4o / mini** | 128k | 高 | 兜底（质量上限） |

> 不在 WorkBuddy 对话里跑批量（对话不适合万次级调用）。写成脚本调 API，`ts_code+end_date` 做去重缓存，失败可断点续跑。

### 4.2 Prompt 设计（两路，结构化输出）

**supply（行业供需景气度）** — 输入：该公司 MD&A 摘要 + 已知 `industry`（库字段，不靠模型识别）
```
请基于以下「{industry}」行业公司的 MD&A，判断该公司所处行业的供需景气度：
1. 供需格局: 供不应求 / 紧平衡 / 供需平衡 / 宽松 / 严重过剩
2. 景气度趋势: 强上行 / 上行 / 平稳 / 下行 / 强下行
3. 产业链位置与议价力: 强势 / 中性 / 弱势
4. 关键证据(引用原文要点)
仅输出 JSON: {"pattern":_, "trend":_, "chain_power":_, "evidence":_}
```
**moat（护城河）** — 输入：MD&A 摘要
```
请识别该公司护城河，对六维逐项判断是否存在及强度(强/中/弱/无)：
- 品牌   - 资格/牌照壁垒   - 成本优势(规模/工艺/资源)
- 渠道/网络  - 技术/专利   - 客户转换成本
输出 JSON: {"dimensions":{...}, "moat_strength":"强/中/弱", "evidence":_}
```

### 4.3 输出契约
- **严禁模型直接给 0–100 分**（漂移不可控）。模型只输出**定性档位 + 证据**。
- 数值映射在阶段四由代码完成，保证可比、可复算。

## 5. 阶段四 · 评分映射与落库

### 5.1 数值映射
| supply | pattern→分 | trend→分 | chain→分 |
|---|---|---|---|
| 供不应求/强上行/强势 | + | + | + |
| 严重过剩/强下行/弱势 | − | − | − |
| （5 档线性映射到 [-100,100]） |

| moat | 强=+1 / 中=+0.5 / 弱=0 / 无=−0.3，六维等权合成 raw |
|---|

### 5.2 标准化（关键：与现有因子可比）
- **supply**：行业景气度是**行业属性**，同一行业内个股应趋同、跨行业不可比 → 做**行业内中性化**（行业内 rank_to_score，与 `cal_cash_factor` 的 R3/R4 同法）。但更优：直接作为**行业层结论**覆盖该行业全部个股，避免个股噪声。
- **moat**：公司级护城河 → **全市场 robust_z_to_score**（与现有 profit/growth 同法），映射到 [-100,100]。

### 5.3 季频 → 周频填充（必做）
MD&A 是季频（每报告期一份），`stock_factor` 是周频。
- 策略：`(ts_code, end_date)` 算出 supply/moat 后，**前向填充**到该报告期披露后至下一报告期前的所有周截面。
- 实现：落库时 JOIN `stock_factor` 所有 ≥ ann_date 且 < 下一 ann_date 的周行，批量 UPDATE supply/moat。

### 5.4 落库
复用 `upsert_stock_factor`，仅更新 supply/moat 两列，幂等可重跑。

## 6. 阶段五 · 验证（复用现有能力）
- **相关性矩阵**：supply/moat 与现有 7 因子的 Pearson，重点查 `moat vs profit`（应中低，否则冗余）、`supply vs valuation`。
- **IC / IR**：接入 `src/analyze_factor_ic.py`，算 12 周 / 60 周 IC。
- **人工抽检**：抽样读 LLM `evidence`，确认档位判断合理（防模型瞎编）。

## 7. 阶段六 · 自动化与专家角色

### 7.1 WorkBuddy 自动化任务
```
触发: 每月 1 次 + 财报季(4/8/10月) 加权
  1. 抓取新披露 MD&A → stock_mda (增量, 按 ann_date 增量)
  2. 批量 LLM 分析 (仅未分析的新报告期)
  3. 评分映射 + 季→周 前向填充 → stock_factor
  4. 出报告: 因子分布 / Top 名单 / 行业景气度热力 / 新鲜度
```
> 周更原管线（`update_weekly` + `cal_factors_weekly`）保持独立；supply/moat 是**季频**补充，不塞进周更（避免 5h 周更被拖爆）。

### 7.2 专家能力如何介入
- **批量打分**：脚本调 LLM API（非对话式 Expert，量级不匹配）。
- **质量校验**：用行业研究 / AI 情报类 **Expert** 对 `supply` 的**行业景气度结论**做抽样复核（专家读行业研报交叉验证模型判断）。
- **护城河质证**：对 moat 头部/尾部样本，Expert 结合公司基本面交叉验证。

## 8. 量级与成本（必须裁剪）

| 范围 | 报告份数 | 估算 token | 评价 |
|---|---|---|---|
| **全历史** 2012–2026 全量 | ~9.5 万 | 数十亿 | ❌ 不现实 |
| 近 5 年 2021–2026 主池 | ~4 万 | 数亿 | 重，二期 |
| **MVP 近 3 年 主池(剔 ST/次新/北交所)** | ~2.8 万 | 数千万 | ✅ 首跑验证 |
| supply 改行业聚合（31 行业×17期≈500） | ~500 | 千万级 | ✅ supply 最优降本 |

- **supply 强烈建议行业聚合**：先聚合同行业多家 MD&A 或按行业综述分析，得行业景气度再赋个股 → 量级从万级降到百级。
- 成本粗估（MVP，DeepSeek 档）：~2.8 万份 × 摘要链 2–3 轮 ≈ 几十到百元级；用 GLM-4-Long 长窗一次喂入可再降轮数。

## 9. 关键工程风险与对策

| 风险 | 对策 |
|---|---|
| 年报 PDF 解析失败（扫描件/表格混排） | 优先文本版年报；PDF 走 OCR + 版面模型；失败计数为空、可重跑 |
| 长文本超窗口截断丢信息 | 摘要链 / 长上下文模型 |
| LLM 评分漂移、跨期不可比 | 模型只出定性档位，数值与标准化由代码统一完成 |
| 行业识别错误拖垮 supply 中性化 | **直接用库内 `industry` 字段**，不让模型识别 |
| 成本失控 | 去重缓存 + 范围裁剪 + 便宜模型 + supply 行业聚合 |
| 模型编造证据 | 抽检 evidence + IC 异常监控 |
