## 用户需求

用户不再需要因子库（FactorLibrary / FactorValue）相关功能，要求从项目中彻底移除相关代码。

## 产品概述

对 `buffeet` 量化分析项目的数据库层与因子计算层进行瘦身，删除因子字典表、因子值表、对应的批量写入/读取函数，以及因子指标计算与入库逻辑，使代码库不再包含任何因子库痕迹。

## 核心特性

- 从 `database.py` 删除 `FactorLibrary`、`FactorValue` 两张 ORM 表，以及 `upsert_factor_value`、`read_factor_matrix` 两个函数，并连带清除仅服务于因子库的常量（如 `_FACTOR_VALUE_CHUNK`）、建表索引与导入，不留死代码。
- 从 `factor.py` 保留前 178 行（模块说明、三个截面归一化函数、`FACTOR_REGISTRY` 列表、`seed_factor_library` 函数及所需导入），删除 178 行之后的全部因子计算、入库与测试入口代码。
- 删除后保证 `import database` 与 `import factor` 无导入错误，且全仓库无遗留引用。

## 技术栈

- 语言：Python 3（项目现有）
- ORM：SQLAlchemy 2.0（DeclarativeBase / Mapped / mapped_column）
- 数据处理：pandas / numpy（仅 factor.py 保留的归一化函数使用）
- 数据库：SQLite（通过 `config.DATABASE_URL` 配置）

## 实现方案

### 总体策略

采用「按需裁剪、保留边界」的方式：database.py 做减法删除因子专属符号；factor.py 保留前 178 行并清理其中为后续代码服务的多余导入，删除 178 行之后的全部内容。删除后通过导入冒烟测试验证。

### 关键技术决策

1. **database.py 整段删除因子符号**：`FactorLibrary`/`FactorValue` 类定义、`upsert_factor_value`/`read_factor_matrix` 函数、以及 `_FACTOR_VALUE_CHUNK` 常量和任何引用这两张表的索引定义（如 `IX_factor_value_*`）一并移除。这些符号除 factor.py 外无任何外部引用（data_fetch.py 仅引入其它表与 upsert 函数），删除安全。
2. **factor.py 保留前 178 行**：第 1–178 行包含归一化纯函数（被潜在复用价值保留）、`FACTOR_REGISTRY`、`seed_factor_library`。但 `seed_factor_library` 仍依赖 `FactorLibrary` 与 `get_session`，因此保留这两个导入；移除 `FactorValue`、`StockDailyBasic`、`StockWeekly`、`StockWeeklyIndicator`、`StockFinaIndicator`、`upsert_factor_value` 等仅在第 179 行之后使用的导入，避免未使用导入。
3. **第 179 行起整段删除**：包含 `normalize_by_date`、`_to_long`、`_compute_and_upsert_by_date`、`_build_filtered_df`、`_compute_*_factors`、`compute_factor_library` 及 `__main__` 测试入口。其中 `_build_filtered_df` 仅内部使用，随之一并移除，不留孤儿函数。

### 性能与可靠性

- 本次为纯删除操作，无新增计算或 I/O 路径，不影响运行时性能。
- 风险极低：删除前已确认无外部引用。删除后通过 `python -c "import database, factor"` 冒烟测试兜底。

## 实现要点

- **database.py**：定位 `FactorLibrary`（约 1907 行起）、`FactorValue`（约 1954 行起）、`_FACTOR_VALUE_CHUNK`（约 1901 行附近）、`upsert_factor_value`（约 2065–2130）、`read_factor_matrix`（约 2146–2245）。注意检查文件末尾或建表脚本中是否有引用这两张表的 `Index` 定义或 `create_all` 相关注释，一并清理。检查 `Base.metadata` 或 `init_db` 是否有显式建表逻辑需要同步调整。
- **factor.py**：删除第 179 行至文件末尾；清理第 14–23 行 `from database import (...)` 仅保留 `FactorLibrary`、`get_session`（供 `seed_factor_library` 使用），其余因子表/函数导入移除。
- **blast radius 控制**：不修改 data_fetch.py、main.py 及其它模块；不改动非因子表的 ORM 定义与 upsert 逻辑。

## 架构设计

删除后模块职责：

- `database.py`：仅保留行情/基本面/日历等数据表的 ORM 与 upsert 函数，因子相关能力整体移除。
- `factor.py`：退化为「因子归一化工具 + 因子字典种子」模块，不再具备计算与入库能力。

无新增架构模式，保持现有扁平模块结构。
