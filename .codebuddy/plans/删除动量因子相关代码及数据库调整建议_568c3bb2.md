## 用户需求

- 项目整体不再需要动量因子，需彻底删除动量因子相关代码（函数、注册表项、ORM 模型列、分析脚本、测试入口及相关注释）。
- 必须保留被其他因子复用的共享底层资源：取数函数（get_weekly_by_trade_date、get_weekly_indicator_by_trade_date）与基础表 StockWeekly / StockWeeklyIndicator 及其字段（open/close/vol/boll_mid/ma60），仅删除动量专属逻辑。
- 数据库仅提供调整策略建议，由用户手动调整，AI 不执行任何 DB 变更。

## 核心范围

- 代码删除：src/factor.py、src/database.py、src/analyze_factor_ic.py 中全部 momentum / 动量 引用。
- 产出建议：factor_library 表 momentum 列的处理与一致性策略。

## 技术栈

- 现有项目：Python + SQLAlchemy ORM + pandas，无新增依赖、无新增模式。

## 实现方案

- 采用"精准删除 + 引用一致性校验"策略：仅移除动量因子专属代码，保留反转/波动率因子复用的取数函数与基础表字段。
- 重点保证四处"列清单"与 ORM 模型同步移除 momentum，避免遗漏引用导致运行期 KeyError 或 SQLAlchemy 映射错位：

1. factor.py 的 `FACTOR_REGISTRY`
2. database.py 的 `_FACTOR_FIELDS`（upsert 按列写值）
3. factor.py 的 `cal_all_factors.expected_cols`
4. analyze_factor_ic.py 的 `FACTORS` 与 SQL `SELECT`

## 数据库调整策略建议（仅建议，不执行）

1. **备份优先**：任何 DDL 前对表做备份
`CREATE TABLE factor_library_bak AS SELECT * FROM factor_library;`
2. **列处理决策（推荐彻底删除）**：
`ALTER TABLE factor_library DROP COLUMN momentum;`
代码已不再写该列（`_FACTOR_FIELDS` 已移除 momentum），DROP 最彻底、无孤儿列。
若需保留历史回溯，可保留列但停止写入（代码侧已停写），历史数据只读留存。
3. **历史数据清理（可选）**：已落库 momentum 历史分无用途，DROP COLUMN 会一并清除；若保留列则
`UPDATE factor_library SET momentum = NULL;` 亦可。
4. **ORM 一致性**：代码侧已删 `StockFactor.momentum` 映射，手调 DB 后须 DB 与 ORM 二者一致（都删或都留），否则查询/upsert 会因列不匹配报错。
5. **约束检查**：确认 momentum 无独立索引/外键（通常无），DROP COLUMN 无障碍。
6. **分析产出**：output/ic_industry_all.csv、output/ic_ir_summary.csv 含 momentum 行，因子删除后可重跑 analyze_factor_ic.py（已移除 momentum）重新生成，或手动删除对应行。
